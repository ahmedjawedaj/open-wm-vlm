# Dataset card

## Scope and provenance

Tetris-2D and Tetris-3D are synthetic rotation analogy datasets reconstructed from the WM-VLM description. Geometry, rendering and records are generated by this repository. Original paper images and original dataset files are not included. The independently generated outputs use the repository's MIT license.

The task is intended for controlled spatial reasoning research. It is not evidence of real-world physics understanding, navigation safety or broad intelligence. Matching split sizes does not make it the authors' benchmark.

## Fields and images

| Field | Role |
|---|---|
| `id`, `task`, `split`, `index`, `variant` | Identity and regeneration metadata |
| `question`, `refs`, `query`, `options` | Ordinary question inputs. Coordinates are rendered to images, not supplied as text to B0/B1 |
| `steps`, `actions` | Ground-truth action supervision |
| `states` | Symbolic query followed by one state per action |
| `answer` | Zero-based option index |
| `answer_label` | Uppercase option letter |

Ordinary inference uses `question_images` in reference-before/reference-after, query, options order. Oracle baselines intentionally receive additional supervision and must be labelled accordingly. `sample_sheet` is a diagnostic visualization containing answers.

## Reproducibility and splits

Default configs fix the seed and split order. The whole-dataset SHA-256 is the hash of concatenated per-split hex digests in config order. Per-split hashes cover actual UTF-8 JSONL bytes. Manifests also contain config and generator versions and the Pillow version. They do not hash image pixels or guarantee identical rendering with every dependency version.

ID tests use seen shape pools. The 3D C-ID pool contains held-out shape classes of seen cell counts. OOD uses seven-cell shapes when train uses four to six cells. Both references and queries follow their split's pool. Mirror-related classes stay in the same pool. See [implemented protocol](dataset_protocol.md) for reconstruction choices.

The duplicate key contains symbolic references and query only. It deliberately ignores hidden traces and distractor permutations. Pixel-level collisions from 3D occlusion are not ruled out. Query-pose/net-rotation configurations may recur with different references. The author's disjoint configuration-pool protocol has not been reproduced.

## Limitations that affect research claims

1. The fixed isometric view can hide cubes. Distinct option images and a unique symbolic rotation do not prove a visually unambiguous question. A visual ambiguity audit remains open.
2. Different action traces can produce the same net rotation. A before/after analogy determines the net rotation but not the hidden action decomposition. Trace prediction should accept equivalent valid paths rather than demand one arbitrary sequence.
3. `depth3_test` changes the supervision trace length, while the visible task still asks for a net rotation. In 2D all turns reduce to one of four orientations. In 3D the rotation group is finite too. This split alone cannot establish depth generalization. Use an explicit action-conditioned rollout task or visible intermediate observations for that claim.
4. The paper shows a final-only 2D state and repeated-axis 3D quarter turns. This implementation stores every 2D action state and disallows consecutive repeated 3D axes. These are known deviations, not unspecified details.
5. Shapes are small, centered, uniformly colored and rendered from a fixed camera. Conclusions may depend on these choices. Sampling is not uniform over all possible questions or answer labels, though counts are reported in the full audit.
6. There are no model scores, trained weights or model integrations in this release.

Full local generation reports are in [the 2D audit](dataset_stats_tetris2d.md) and [the 3D audit](dataset_stats_tetris3d.md). A full second-machine verification of generator version 2 and a 200-sample independent visual review remain open.
